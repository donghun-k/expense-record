# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 소비해야 하는지 정의한다.

## 탐색 전에 읽을 것

- **`CONTEXT.md`** (루트), 그리고
- **`docs/adr/`** — 작업하려는 영역과 관련된 ADR을 읽는다.

이 파일들이 없으면 **조용히 진행한다**. 부재를 지적하거나 미리 생성을 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture` 경유)이 용어나 결정이 실제로 확정될 때 지연 생성한다.

## 파일 구조

이 저장소는 **단일 컨텍스트**다 (단일 Next.js 앱):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-notion-as-backend.md
│   └── 0002-server-actions-only.md
└── ...
```

## 용어집의 어휘를 사용하라

출력이 도메인 개념을 명명할 때(이슈 제목, 리팩터 제안, 가설, 테스트 이름 등) `CONTEXT.md`에 정의된 용어를 사용한다. 용어집이 명시적으로 피하는 동의어로 흘러가지 않는다.

필요한 개념이 아직 용어집에 없다면 그것은 신호다 — 프로젝트가 쓰지 않는 언어를 만들어내고 있거나(재고할 것), 실제 공백이 있거나(`/domain-modeling`에 기록).

## ADR 충돌을 표시하라

출력이 기존 ADR과 모순되면 조용히 덮어쓰지 말고 명시적으로 드러낸다:

> _ADR-0007(Notion 백엔드)과 모순됨 — 그러나 다시 검토할 가치가 있는 이유는…_
